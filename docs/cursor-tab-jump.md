# 动态词库光标定位与 Tab 跳转

本次修复需在 Windows 重新构建并安装 Weasel；仅重新部署 Rime 配置不会更新前端代码。保留原来的 `style/cursor_tab_jump: true` 配置即可，不需要修改词库语法。

## 修复内容

- 在 `OnKeyDown` 执行 Tab 跳转，兼容一次或多次 `OnTestKeyDown`，也兼容直接调用 `OnKeyDown` 的应用。跳转成功后同时消费 Tab 的释放事件。
- 填空中普通文字上屏时保留剩余跳转目标。
- 把首次定位推迟到 `EndComposition` 之后。持久文本上下文使用 TSF 范围；临时文本上下文使用提交后的方向键定位，避免依赖提交后失效的范围。持久上下文拒绝首次选区设置时也尝试方向键方式。
- 方向键定位事件绕过 Rime 处理，并使用私有结束标记收尾；兼容 TSF 回调丢失 `dwExtraInfo` 的情况。
- 候选翻页、拼音未上屏时的方向键操作保留跳转会话，由 Rime 处理，不改变编辑区跳转距离。
- 上屏后当前填空内的左右键操作保留会话。兼容模式只按真正传给编辑区的按键修正跳转距离；重复的 `OnTestKeyDown` 不重复计数。左右移动后继续输入或删除字段内的后续字符，Tab 仍定位到下一字段或模板末尾。
- Esc、鼠标操作、切换上下文或窗口，以及上屏后的上下跨行、Home/End、Shift+方向键和 Ctrl/Alt 快捷键仍退出跳转。拼音仍在候选状态时，Tab 交给原有方案处理；应先选词上屏再跳转。

Chromium 的提交路径会以 `kMoveCursorAfterText` 插入文本，且将上下文标记为 `TS_SS_TRANSITORY`，因此提交前设置选区、长期保存范围不能作为跨应用定位的共同前提。参考 [Chromium TSFTextStore 实现](https://github.com/chromium/chromium/blob/main/ui/base/ime/win/tsf_text_store.cc)。

## 标点按键白名单

在 `Rime/weasel.custom.yaml` 的已有 `patch:` 下配置：

```yaml
patch:
  "style/cursor_tab_jump": true
  "style/cursor_punct_jump_keys": ",.;:!?"
  "style/cursor_punct_jump_scope": last
```

白名单填写实际按键产生的半角字符：`,` 对应逗号键，`.` 对应句号键，`:` 对应 Shift+分号，`?` 对应 Shift+/，`!` 对应 Shift+1。最终输入中文还是英文标点，仍由 Rime 当前设置决定。删除字符即可缩小白名单，空字符串 `""` 关闭自动跳末尾。未配置时默认关闭；本项目用户配置已写入上述白名单。修改后重新部署配置。

仅在跳转会话有效时触发，支持先选词上屏后按标点，也支持直接用白名单标点确认候选。默认范围 `last` 只允许在最后一个填空触发；`any` 允许在任意字段触发，并直接跳到整个模板末尾。例如 `（以下简称“xxx|”）` 按逗号后成为 `（以下简称“xxx”），|`。`last` 避免跳过未填字段；`any` 会跳过后续字段，尚未替换的字段提示文字仍保留在模板中。Tab 和 Shift+Tab 的逐项跳转行为不受该范围设置影响。

白名单外的标点按键仍在填空内输入。字母编码、候选词、宏及其他文本提交产生的标点，不经过按键判断，不会触发跳末尾；白名单不能填写中文标点 `，。` 或字母编码。Ctrl/Alt/Win 组合键不触发。候选状态下，原方案的按键绑定优先：分号选第二候选、标点翻页等操作不会被改成自动跳末尾。

原生 TSF 选区和方向键兼容模式都会在跳转后通过后续私有窗口消息，把保存的实体标点按键重新投递到 Windows 输入队列。标点经应用正常的 TSF 按键回调处理，使用新的输入上下文，并保留原字符和 Shift 状态；Rime 透传时由应用正常输入半角字符。窗口消息与方向键结束标记都不直接请求 Rime 上屏，避免微信仍使用旧光标位置，以及 Word 异步读取时被后续抬键响应覆盖。原按键的释放事件从候选分离请求发出时就被消费，防止覆盖尚未读取的候选上屏响应，也防止重复输入。

候选状态下直接按白名单标点时，前端发送一次性分离请求；放在 `key_binder` 之后的 `cursor_punct_split_processor` 先仅提交当前选中的候选。前端收到确认，并等候选实际写入、组合结束后，才跳到模板末尾并将原标点交给 Rime。例如在 `（以下简称“$|”）` 中输入“民法典”的拼音，直接按逗号，结果为 `（以下简称“民法典”），`，不需要先按空格。不会从已提交的字符串中猜测或截取尾部标点。

此路径需要同时更新 Windows 主程序和 Rime 源配置，并重新部署。两个方案均已在 `key_binder` 之后、`punctuator` 之前加入处理器；只替换程序而保留旧方案时，没有分离确认就按原方案处理，不会额外跳转或重复输入标点。

分号用于选择第二候选时，前端保留测试回调对该按键的处理结果，不会因选词刚刚创建了跳转会话，就在正式回调中把同一次分号重新解释为标点。Tab 等快捷键同样区分选词动作和跳转动作。

## 按应用覆盖

可在已有 `patch:` 下按应用进程名覆盖单个选项，例如：

```yaml
patch:
  "app_options/chrome.exe/cursor_punct_jump_keys": ",."
  "app_options/wechat.exe/cursor_punct_jump_scope": any
  "app_options/emeditor.exe/cursor_tab_jump": false
```

以上仅为用法示例，不会默认禁用这些应用。优先级为全局 `style/` → 方案 `style/` → `app_options/<进程名>/`。应用名不区分大小写；未填写的选项继承前一层，显式 `false` 和空字符串 `""` 会覆盖前一层。错误的范围值会被忽略并继承前一层。

`cursor_tab_jump: false` 关闭该应用的 Tab 跳转会话及标点自动跳末尾，保留模板首次上屏的定位行为，与原总开关含义一致。只想关闭标点自动跳末尾而保留 Tab 时，设置该应用的 `cursor_punct_jump_keys: ""`。光标策略按会话保存，应用覆盖在每次响应时单独计算，不会修改其他窗口或方案的基础设置；这些前端选项不会作为 Rime 引擎开关传入。

修改 YAML 后重新部署即可调整规则；首次使用这些新增配置仍需安装包含本次接口改动的 Windows 主程序。

```sh
lua tests/test_cursor_punct_split.lua
python3 tests/test_cursor_punct_bridge.py
python3 tests/test_cursor_tab_jump.py
python3 tests/test_cursor_punct_config.py
python3 tests/test_frontend_reopen.py
python3 tests/test_frontend_undo.py
```

测试编译实际 C++ 方法并在模拟文本存储与按键回调中运行，覆盖持久/临时上下文、中文填空、连续字段、未填字段跳过、重复测试回调、无测试回调、按键释放、选区拒绝、注入失败和焦点变化，也覆盖 Word 延迟读取候选响应、微信在窗口消息期间保留旧选区、实体标点重投递与输入标记丢失。它们不能代替 Windows/MSVC 构建及实际应用测试。

## Windows 验收

在 Word、记事本、Obsidian 编辑区、EmEditor、Chrome 普通文本输入框/多行输入框、微信聊天编辑框逐项测试：

| 词条示例 | 操作与预期 |
| --- | --- |
| `csdw=1,（本页无正文，为《$|》签署页）` | 上屏停在《》之间；输入并上屏“测试合同”；按 Tab 停在最后的“）”之后。 |
| `cstg=1,联系人：$|，电话：$|` | 上屏选中 `$1`；输入“张三”并上屏；Tab 选中 `$2`；输入数字（含小键盘输入）；Tab 到末尾。 |
| 同上 | 不输入内容直接按 Tab，依次跳过选中的标记，最后一次 Tab 折叠到末尾。 |
| 同上 | 输入拼音时按 PageUp/PageDown 翻页，或用方向键移动拼音光标、选择候选；选词上屏后 Tab 仍跳到下一项。 |
| 同上 | 字段文字上屏后，按左右键在当前字段内移动，继续输入或 Delete 删除字段内后续字符；Tab 仍跳到下一项，最后一项跳到末尾。 |
| 同上 | 填空过程中按 Esc、用鼠标重新定位或切换窗口后，Tab 恢复应用原有行为。 |
| `csdw=1,（以下简称“$|”）` | 上屏“测试公司”后按逗号，结果为 `（以下简称“测试公司”），`；Shift+/ 在末尾输入问号。 |
| 同上 | 输入“民法典”的拼音后不按空格，直接按逗号；候选进入引号内，逗号在右括号之后，结果为 `（以下简称“民法典”），`。 |
| 同上 | 使用未加入白名单的标点键，或通过字母编码选择标点候选；标点仍插入当前填空内。 |
| 多字段词条 | `last` 下非最后字段输入白名单标点仍留在字段内；`any` 下从第一字段也能直接跳到整个模板末尾输入标点。 |
| 微信标点顺序 | 模板填入“xx”并上屏后按逗号，应得到 `（以下简称“xx”），`，逗号不能出现在引号内。 |
| Word 分号选词 | 使用分号选择含占位符的第二候选，光标应进入填空；不得额外插入分号或空字符。随后输入并上屏内容，再按白名单标点，应正常跳末尾。 |
| 应用配置 | 在两个应用间切换并使用不同白名单/开关；未设置覆盖的应用仍继承全局值，应用覆盖不应影响其他窗口。 |
| 普通无占位符词条 | 正常上屏到末尾，Tab 保持原有行为。 |

方向键兼容方式按模板中未改动的后缀计算距离，合并 UTF-16 代理对和 CRLF；组合附加符、ZWJ 表情序列、双向文本以及会自动改写模板后缀的编辑器插件，仍需单独实测。一次移动超过 4096 步、按住 Ctrl/Alt/Shift 选择模板、系统拒绝注入时会停止跳转。用户已在 `0.17.4.0.6d8bdbd` 验证 EmEditor 和 Chrome 正常。该版本的 Word 标点丢失、微信先输入标点后跳转，已补充异步响应与输入边界的模拟回归；本次实体按键重投递修复仍需在 Windows 上构建并实测。

## CopyQ / QuickPanel 外部模板

新增按活动 TSF 线程接收外部模板的接口。QuickPanel 恢复目标窗口焦点后提交模板，在实际异步写锁中校验当前上下文，再复用本文件所述解析、定位及跳转逻辑。c+Tab、Quicker 或其他启动入口使用相同接口；模板上屏不依赖先输入 Rime 编码。

已有 YAML 策略与应用覆盖继续有效。普通剪贴板粘贴不识别占位符，QuickPanel 通过 `weasel_template_tabs` 指定模板标签页。具体配置、协议与验收步骤见 [QuickPanel 模板说明](../../CopyQ_QuickPanel/TEMPLATES.md)。
